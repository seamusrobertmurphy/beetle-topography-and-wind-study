# Red-stage classification

The Landsat red-stage pipeline built for this manuscript, 2026-08-19. Code lives
in `01.manuscript/beetle-topography-wind-study.qmd` under "Red-stage
classification", not in `02.inputs/`, because all rgee code belongs in the
manuscript. See [[parent-study-audit]] for what could not be reused and why.

- 2026-08-19: rgee 1.1.8 works on this machine against Earth Engine project `murphys-deforisk`, driving the pre-existing virtualenv at `~/.virtualenvs/rgee` (python 3.14, ee 1.7.30). Credentials are at `~/.config/earthengine`. Matters because no new environment is needed and none should be created.
- 2026-08-19: SCS+C terrain correction measurably works here. On the first 2003 Landsat 5 scene the correlation between NIR and the illumination term falls from 0.2716 uncorrected to 0.0502 corrected. Matters because the study tests terrain effects, so the correction has to be demonstrated rather than assumed, and this is the number that demonstrates it.
- 2026-08-19: `ee$Reducer$linearFit` returns null where a scene is wholly masked over the grid, which kills the whole map with "Number.divide: Parameter 'left' is required". Guard with `ee$Algorithms$If` and set C very large, which drives the SCS+C factor to one and passes the scene through unchanged. Matters because the failure is intermittent and looks like a code bug rather than a data gap.
- 2026-08-19: a GeoTIFF written from an Earth Engine byte or integer image takes zero as its nodata value, so exporting a 0/1 classification silently turns every unattacked cell into NA. The first export came back 100 per cent attacked in all ten years, with 205,825 ones and 238,280 apparent NAs summing exactly to the 444,105 cells of the grid. Export the continuous decision value scaled and offset away from zero, and threshold locally. Matters because the arithmetic underneath was correct throughout and nothing in the run failed.
- 2026-08-19: `ee$Classifier` carries its training features into every request that uses it, so classifying an image with a classifier trained on sampled composites fails with HTTP 400 while the same composite downloads fine alone. A linear kernel is a plane, so fit locally with `kernlab::ksvm(kernel = "vanilladot", scaled = FALSE)` on self-standardised predictors and apply the weights as a band expression; it reproduces `predict()` exactly. Matters because the 400 looks like a network fault and is not.
- 2026-08-19: `getDownloadURL` with `crsTransform` but no `dimensions` makes Earth Engine compute over the entire CRS extent and fails at 840 MB against a 50 MB cap. Use `scale` plus `region` instead and resample onto the analysis grid locally with `terra::resample(method = "near")`. Matters because the crsTransform route looks like the exact-alignment answer and is a dead end.
- 2026-08-19: the classification agrees with the aerial survey on 68 per cent of held-out cells, kappa 0.36, but that figure is an artefact of balanced sampling and must not be quoted on its own. Training drew 250 attacked and 250 unattacked cells per year, implying a prior of one half against a true prevalence of 0.09 to 1.27 per cent, so at its own threshold the model calls 27 to 66 per cent of the grid attacked. Matters because the pooled kappa looks publishable and the map is not.
- 2026-08-19: with the threshold calibrated per year so classified area equals surveyed area, the classification hits 0.0 to 2.6 per cent of the survey's attacked cells, lift 0.00 to 4.81 against a chance value of 1.00, and four of nine years share no cells with the survey at all. Matters because this, not the kappa, is the number that decides the response layer: the map is close to uninformative about where attack was, so the aerial survey stays the response and no survival model can be fitted on the classified series.

It is the only Landsat 7 year and the sensor has been scan-line-corrector-off since May 2003.
